# API reference

The backend exposes a local-only HTTP API. All paths below are prefixed with
`/api/v1`. The desktop app receives the base URL from the Electron main process;
the port is assigned at startup.

- **Base URL (installed app):** `http://127.0.0.1:<port>/api/v1`
- **Auth:** header `X-Slothy-Token: <per-launch token>` on every request when the
  backend runs in desktop mode. The token is generated by the Electron main
  process and never exposed to the renderer.
- **Content type:** JSON unless noted. Attachments use raw binary bodies.
- **Errors:** `{"code": "...", "message": "...", "request_id": "..."}` with a
  matching HTTP status. `422` validation errors always use code
  `VALIDATION_ERROR`.

## 6. Chat and run control

| Method | Path | Purpose |
|---|---|---|
| POST | `/chat` | send a message; returns `ChatResult` (JSON) or an SSE stream |
| POST | `/threads/{id}/resume` | resume a paused or interrupted run |
| GET | `/threads/{id}/approval` | pending tool review for a thread |
| POST | `/threads/{id}/approval/{approval_id}` | approve or reject the pending batch |

### Request highlights — `POST /chat`

```json
{
  "thread_id": "uuid-or-null",
  "message": "帮我把方案整理成文档",
  "mode": "work",
  "model": "provider/model-id",
  "reasoning_effort": "medium",
  "stream": true,
  "project_id": "workspace-id-or-null",
  "approval_policy": "ask",
  "attachment_ids": ["file-id"],
  "personalization_enabled": true
}
```

- `thread_id: null` creates a new conversation; `mode` fixes the tool set
  (`chat` = safe tools only, `work` = all tools).
- Pending approval: non-stream mode returns **202** with a `ToolReview` body
  instead of a `ChatResult`.
- If a thread has an unfinished run, new messages are rejected with
  `409 RUN_PENDING`; resume or clear it first.

### Response — `ChatResult`

```json
{
  "run_id": "…",
  "thread_id": "…",
  "response": "…",
  "profile_version": 4,
  "used_memory_ids": ["…"],
  "activity": [],
  "metrics": { "input_tokens": 1234, "cached_input_tokens": 900 }
}
```

### SSE events (`stream: true`)

Frames use `event: <name>\ndata: <json>\n\n`.

| Event | Payload | When |
|---|---|---|
| `session` | `{thread_id}` | stream opened |
| `delta` | `{text}` | incremental assistant text |
| `activity` | `{run_id, items[], metrics}` | run activity changed (tool/model/context steps) |
| `approval_required` | `ToolReview` | run paused for tool approval |
| `done` | `ChatResult` | run completed |
| `error` | `{code, message, request_id}` | HTTP error while streaming |

### Approval flow

1. `POST /chat` (or resume) returns `approval_required` or **202** with
   `approval_id`.
2. `GET /threads/{id}/approval` returns the same review (or `null`).
3. `POST /threads/{id}/approval/{approval_id}` with `{"approved": true|false}`.
4. The run continues: approved calls execute, rejected calls are returned to the
   model as typed errors.

## 7. Examples

```powershell
# health
curl http://127.0.0.1:8000/api/v1/health

# non-streaming chat
curl -s -X POST http://127.0.0.1:8000/api/v1/chat ^
  -H "Content-Type: application/json" ^
  -H "X-Slothy-Token: <token>" ^
  -d '{"message":"你好"}'

# streaming chat (PowerShell 7)
curl.exe -N -X POST http://127.0.0.1:8000/api/v1/chat `
  -H "Content-Type: application/json" -H "X-Slothy-Token: <token>" `
  -d '{"message":"你好","stream":true}'

# profile and versions
curl http://127.0.0.1:8000/api/v1/profile -H "X-Slothy-Token: <token>"
curl "http://127.0.0.1:8000/api/v1/profile/versions?limit=20"
```

When the Electron shell runs the backend, use the port printed on the backend's
stdout (`{"event":"listening","port":N}`); the token lives only in the main
process.

## 8. Notes

- The API is single-user by design (`local-user`); multi-user isolation is a
  future milestone, and `user_id` is never accepted from clients as authorization.
- SSE has no heartbeat or retry protocol; a dropped connection ends the stream,
  and the run remains resumable from its checkpoint.
- Attachment upload limit: 2 MiB per file, 24 MiB per thread.
